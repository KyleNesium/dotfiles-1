# Project Folder Convention

Every Kyle track lives in its own folder under `D:\Ableton Projects\` with a consistent structure. This prevents the WIP graveyard problem and makes a track recoverable / shareable / portable at any stage.

## Folder name format

`D:\Ableton Projects\YYYY-MM - Track Name\`

Examples:
- `D:\Ableton Projects\2026-06 - First Steps\`
- `D:\Ableton Projects\2026-07 - Ember\`
- `D:\Ableton Projects\2026-08 - Onire Remix\`

Why `YYYY-MM` prefix:
- Sorts chronologically by default
- A year from now you can find "the track I started in June 2026" without metadata
- Avoids exposed-creation-dates from file metadata which can shift

## Standard folder contents

```
2026-06 - First Steps/
├── First Steps.als                ← the Ableton project file (named WITHOUT date prefix for cleaner display)
├── First Steps.als.backup         ← Ableton's auto-backup (auto-generated by Live)
├── Backup/                        ← Ableton auto-backups (auto-generated)
├── Samples/                       ← Live's auto-collected sample copies
├── notes.md                       ← YOUR notes — production decisions, what's working, what's not
├── references/                    ← reference tracks for this track specifically
│   ├── ezequiel-arias-prisma.wav  ← (or just URLs in references.md)
│   └── ...
├── stems/                         ← rendered stems for collab handoff
│   ├── 01-drums.wav
│   ├── 02-bass.wav
│   ├── 03-pads.wav
│   └── ...
├── bounces/                       ← quick render previews for phone listening / Slack sharing
│   ├── 2026-06-15 - rough mix.mp3
│   ├── 2026-06-22 - drums revised.mp3
│   └── ...
├── master/                        ← final renders at all LUFS targets
│   ├── First Steps - master streaming -14LUFS.wav
│   ├── First Steps - master DJ -10LUFS.wav
│   ├── First Steps - master club -8LUFS.wav
│   └── First Steps - pre-master no-chain.wav  ← for sending to external mastering engineer
├── artwork/                       ← cover art at all required sizes
│   ├── 3000x3000.png              ← Spotify/Apple Music master
│   ├── 1280x720.jpg               ← YouTube
│   ├── 1080x1080.jpg              ← Instagram square
│   ├── 1080x1920.jpg              ← Instagram story / TikTok
│   └── source.psd                 ← editable source
└── release/                       ← release-ready packages
    ├── metadata.md                ← title, ISRC, BPM, key, writer credit, etc.
    └── distributor-upload/        ← what gets uploaded to Distrokid/Amuse/etc.
```

## The `notes.md` template

Create this file the moment you start the project. Update it as you work.

```markdown
# [Track Name]

## Initial intent
- **Genre target:** progressive-house / melodic-techno / etc.
- **Tempo:** 122 BPM
- **Key:** A minor
- **Reference tracks:** [3-5 specific tracks + timestamps for what makes them work]
- **Mood:** [1 sentence — "patient build, hypnotic groove, emotional drop at 5:00"]
- **Why this track exists:** [1-2 sentences — what's the personal reason]

## Decisions log
- 2026-06-15: started with K-002 bass + K-007 pad in Am
- 2026-06-16: added arp on K-004, found the hook
- 2026-06-18: tried 124 BPM, brought back to 122 — felt forced
- 2026-06-22: breakdown at 3:30 isn't long enough — extending to 16 bars

## Open questions
- Does the bass need more presence in the 200-400 Hz range?
- Is the lead synth too forward in the final drop?
- Should there be a vocal element or is instrumental better here?

## Reference comparisons
- Played alongside Ezequiel Arias — Prisma. My drums are 2 dB louder than his.
- Played alongside Lane 8 — Atlas. My pad sounds smaller. Maybe add more reverb send.

## Status: WIP / Mixing / Mastering / Released / Shelved
- Current: WIP
- Started: 2026-06-15
- Last touched: 2026-06-22

## Release plan (when ready)
- Target release date: TBD
- Distributor: TBD
- Label submission: maybe Sudbeat — would need approval
- Promotional plan: 30-sec teaser on Instagram, full release on Spotify
```

## Pre-track checklist (before starting a new project)

When sitting down to start a new track:

- [ ] Decide track name (or use a placeholder like "Untitled-2026-06-23")
- [ ] Create the folder: `D:\Ableton Projects\2026-MM - Name\`
- [ ] In Ableton: File → Save Live Set As… → save into the folder as `Name.als`
- [ ] Create `notes.md` with the template above filled out for "Initial intent"
- [ ] Optional: create empty `references/`, `stems/`, `bounces/`, `master/`, `artwork/`, `release/` subfolders so they exist when needed

Total time: 90 seconds. Habit-forming.

## In-progress checklist (during the work)

Every time you sit down to continue the track:

- [ ] Open the `.als` from its folder (NOT from Live's recent files — go through the folder)
- [ ] Open `notes.md` in a code editor / Obsidian — keep it visible alongside Live
- [ ] Add a dated entry to "Decisions log" when you make a significant choice
- [ ] When you've worked 30+ min: Save Live (Cmd/Ctrl+S) AND save the project folder somewhere safe (Dropbox/OneDrive/external — your call)

## Pre-export checklist (before rendering masters)

Before File → Export Audio:

- [ ] Master chain deployed and dialed per [[MASTER-CHAIN]]
- [ ] LUFS reading via Pro-L 2 hits target (-14 streaming / -10 DJ / -8 club)
- [ ] True peak ceiling at -0.3 dBTP
- [ ] No clipping on any individual channel
- [ ] All clip fades respected (no clicks at clip boundaries)
- [ ] Tempo, key, name set correctly in Live's metadata (Cmd/Ctrl+I → Info View)

Render targets:
- `master streaming -14LUFS.wav` — 24-bit, 44.1 kHz (for streaming services)
- `master DJ -10LUFS.wav` — 24-bit, 44.1 kHz (for sharing with DJs)
- `master club -8LUFS.wav` — 24-bit, 44.1 kHz (for sound-system listening tests)
- `pre-master no-chain.wav` — 24-bit, 44.1 kHz, **master chain bypassed** (for sending to external mastering engineer)

Save renders into `master/` subfolder of the project folder.

## Stems export checklist (when sending to a collaborator)

If a vocalist / engineer / remixer needs your project:

- [ ] In Live: Solo each track group, export as audio (Cmd/Ctrl+Shift+E)
- [ ] Render each as 24-bit, 44.1 kHz WAV
- [ ] Name format: `01-KICK.wav`, `02-TOP-DRUMS.wav`, etc. (numbered for ordering)
- [ ] All stems must start at bar 1, beat 1 (Live's "Render Loop" option OFF — render full arrangement)
- [ ] Bounce the master too (`00-MASTER.wav`) for reference
- [ ] Zip the `stems/` folder for sharing

Naming the zip: `First Steps - stems for [collaborator name].zip`

## Backup strategy

Pick ONE and commit:

- **Option A — Cloud-synced project root:** put `D:\Ableton Projects\` inside Dropbox/OneDrive/Google Drive. Every save auto-uploads. Simplest, but watch for sync conflicts if two devices touch the same project.
- **Option B — Manual external drive backup:** weekly `rsync` of `D:\Ableton Projects\` to an external drive. More disciplined but less automatic.
- **Option C — Versioned to git LFS:** `D:\Ableton Projects\` as a git repo with LFS for `.als` and `.wav` files. Best for true version control. More setup.

**Recommended starting point: Option A** (OneDrive — you already have one mounted) for the first 10 tracks, then revisit.

## What goes in version control vs not

**In version control (dotfiles or project git):**
- `notes.md`, `references.md`, `metadata.md` (text — small, easy)
- This file and other identity docs

**NOT in version control (too big or licensed):**
- `.als` files (Ableton project files — can be large)
- `Samples/` (auto-collected by Live — can be GB)
- `master/`, `bounces/` (rendered audio — large)
- Anything in `D:\Presets, Samples and Loops` (license-encumbered)

If you want versioned `.als` history: use git LFS specifically for those. Don't put them in regular git.

## Clean-up periodically

Every 3 months, audit `D:\Ableton Projects\`:

- **Active WIPs:** still being worked on — leave alone
- **Stalled WIPs:** untouched 3+ months — open them, apply the WIP-rescue ritual ([[ARTIST-PROFILE]] → "Burnout-resistance"):
  1. Finish it (set a deadline)
  2. Mine it for ideas (extract usable parts, archive rest)
  3. Formally delete (with a one-line RIP in your project ledger)

This prevents 50+ unfinished projects piling up.
